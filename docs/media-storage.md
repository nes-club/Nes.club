# Хранение медиафайлов

Платформа не хранит картинки сама — она отправляет их на внешний сервис и хранит только URL. Код загрузки находится в `common/images.py`.

## Текущий выбор: Вариант 1 — без медиа-сервиса

`MEDIA_UPLOAD_URL` и `MEDIA_UPLOAD_CODE` **не заданы** в переменных Railway.

**Последствия:**
- Загрузка аватарки сохраняет `None` (аватарка не отображается)
- Картинки в постах, вставленные через URL, не кэшируются через CDN
- Приложение **не падает** — `upload_image_from_url()` при отсутствии `MEDIA_UPLOAD_URL` просто возвращает исходный URL

## Варианты

### Вариант 1 — без медиа-сервиса (текущий)

Не задавать `MEDIA_UPLOAD_URL`. Аватарки не загружаются, всё остальное работает.

### Вариант 2 — vas3k.media (самохостинг)

Оригинальный медиа-сервис от автора движка: https://github.com/vas3k/vas3k.media

Принимает файлы по HTTP POST, хранит на диске (или S3), отдаёт по URL.

Деплой на Railway как отдельный сервис:
1. Создай новый сервис в Railway → Deploy from GitHub → форкни vas3k/vas3k.media
2. Добавь volume для хранения файлов
3. Задай переменные:
   ```
   MEDIA_UPLOAD_URL=https://media.твой-домен.com/upload/
   MEDIA_UPLOAD_CODE=секретный_код
   ```

### Вариант 3 — S3 / Cloudflare R2 / Yandex Object Storage

Заменить `upload_image_multipart` в `common/images.py` на прямую загрузку в S3-совместимое хранилище.

Нужно:
- Добавить `boto3` в зависимости
- Переписать `upload_image_multipart` (~50 строк)
- Задать `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_S3_BUCKET`, `AWS_S3_ENDPOINT_URL`

Cloudflare R2 дешевле AWS S3 и совместим по API.

## Переменные для Вариантов 2 и 3

| Переменная | Описание |
|---|---|
| `MEDIA_UPLOAD_URL` | URL эндпоинта загрузки (вариант 2) |
| `MEDIA_UPLOAD_CODE` | Секретный код для аутентификации (вариант 2) |
| `OG_IMAGE_GENERATOR_URL` | Опционально: сервис генерации OG-превью для постов |
